# Coherent parser and mapper profile

This lane installs an explicitly identified local derivative into a new hosted
Linux profile. It preserves both original published profiles and their source
archives. It is a qualification candidate, not an adopted application migration
or a newly authenticated registry publication.

The profile keeps the raw candidate's manifest, lock and native module resolution
conditions. Every original regular package member is copied from its verified
source. Four chromium-bidi members have explicit effective pins: the Node parser
and its map, and the generated browser mapper and its map. The parser uses the
reviewed type guard. The browser payload is rebuilt from the same guarded input
with Zod 4.6.7. Modified bytes are identified as derivatives; the original npm
integrity does not authenticate them.

The changed Node parser receives a new line-level map to its actual derived
compiled JavaScript. The original TypeScript map remains in the raw publication.
The mapper map preserves its validated mapping deltas and exact compiled-JS
source contents, with portable source labels and the correct output filename.
The linked generated legal text and four original source/compiler notices are
retained in the derivative. This preservation does not complete legal review.

Puppeteer's Chrome BiDi adapter creates a Node BidiServer without an explicit
protocol parser. It does not load the package's precompiled `mapperTab.js` into
Chrome. The earlier paired SDK controls therefore establish that adapter's
browser behavior, not execution of the precompiled embedded mapper.

The new profile checks native Node parser exports using real ESM resolution,
then repeats CDP/BiDi and nominal/synthetic application controls. A separate lane
loads the installed mapper into a real Chrome target through
`Target.exposeDevToolsProtocol`, starts its actual browser bootstrap and exercises
bounded BiDi commands. A second, map-bound inspection copy keeps the full
bootstrap and observes twelve bounded declaration cases inside Chrome. That
inspection copy is not installed into the package and carries no stale generated
map. Each control container has at most three elements.

The browser WindowBidiTransport rejects non-object parameter envelopes before
calling a protocol parser. Scalar wire rejection and direct parser behavior are
recorded separately. Direct API error-contract controls must not be reported as
proof that the same malformed input reaches a parser through that transport.

Both new application builds use the same frozen first-party sources. The existing
Chrome 157 archive and extraction are reused; no additional browser download is
needed. Copies are portable regular files with a 256 MiB cap. The existing 10 GiB
free-space floor is preserved. CI retains manifests, command streams and bounded
images, using reproducible references for the already retained generated mapper
payload/map rather than another full package or browser archive.

These assertions require the exact revision's successful CI receipts and artifact
review. Raw baseline/current findings, publisher/platform/advisory review,
application adoption, maintainer/operator acceptance and the original full D04
and 42-item roadmap remain separate gates. Production remains **NO_GO**.
